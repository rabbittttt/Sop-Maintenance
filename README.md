# SOP计划管理

用于维护月度 SOP 计划的本地应用。网页和 Excel 共用同一份计划数据，支持滚动 M+6、锁单对照、版本维护、导入导出与 Excel 快照备份。

## 启动

1. 首次使用时安装 Python 3.11+，将项目放在 `Project/` 下。
2. 同级存在 `../共享数据/` 时，从 `../共享数据/订单汇总/` 读取订单分析生成的销量文件；独立使用且没有共享目录时仍读取 `input_file/`。点击“网页维护”即可在主表填写汇总代际或独立车型总量、展开改单代际及版本，或增删明细行，再点击“保存修改”；无需选择维护月份或维护粒度。Excel保留导入、导出能力，`../共享数据/SOP计划/SOP计划维护.xlsx` 是可选的同步文件（没有共享根时使用 `input_file/`）；没有它时，启动、网页维护和导出都不会自动创建。成功导入Excel计划后，会在所配置的维护目录自动生成或更新标准维护表，包含统一数据中的完整车型、版本和计划周期；也可到“数据与规则”创建维护Excel。导入校验失败或冲突未处理时，不创建维护表；若计划已保存但文件写回失败，会提示维护表待同步。
3. 双击 `启动工作台.cmd`。环境正常时直接启动；缺少共享环境或 SOP 依赖时，自动创建 `Project/.venv`、安装所需依赖，成功后继续启动，无需单独初始化。服务就绪后自动打开 <http://127.0.0.1:8876/>，启动窗口保持运行。
4. 关闭该命令窗口或按 `Ctrl+C` 即停止工作台，无需独立停止脚本。仅关闭浏览器页面不会停止服务。

重复双击会打开已运行的网页，服务仍由第一次启动的窗口控制。旧版隐藏后台进程会在新入口首次启动时核对工作目录、进程身份及端口后切换；其他服务不受影响。命令行也可运行 `../.venv/Scripts/python.exe server.py --open-browser`；`./start-sop.ps1 -NoBrowser` 适合不自动打开网页的前台运行。

启动脚本默认从自身位置向上定位名为 `Project` 的工作区，只使用其 `.venv`（Windows 为 `.venv/Scripts/python.exe`，其他系统为 `.venv/bin/python`）。Project 的上级目录可以任意改变；嵌套项目也使用同一个共享环境，不再优先项目自己的 `.venv`，也不会改用 PATH 或 Codex 缓存的 Python。显式 `SOP_PYTHON_PATH` 仍可覆盖；相对值按 SOP 项目根目录解析，例如 `../.venv/Scripts/python.exe`。启动前检查 Python 3.10+ 和 `openpyxl`；健康环境不运行安装、不访问包源。仅默认共享环境缺失或依赖缺失时才自动初始化，并复查成功后继续启动。初始化失败会显示原因并停止；损坏的共享环境保留原样，不删除、不覆盖。显式指定的解释器不可用时直接报错，不自动修改它或改用共享环境。运行 `./start-sop.ps1 -CheckRuntime` 可只检查并显示解释器，不启动服务或修改业务数据。

换电脑时先安装符合工作区依赖要求的 Python 3.11+，复制 Project 时排除旧 `.venv`，再双击 `启动工作台.cmd` 自动重建环境。首次创建共享环境时，初始化程序使用本机 Python 创建虚拟环境；看板及依赖安装始终使用选中的共享环境，不修改系统 Python 的包。`setup-environment.ps1` 是启动器内部使用的准备脚本，只安装本项目 `requirements.txt` 中的 SOP 依赖；需要工作区全部依赖时仍可使用 Project 根的共享初始化入口。初始化需要访问配置的 Python 包源；离线电脑可预先准备对应平台和 Python 版本的依赖包。

服务调用的 Excel 生成脚本会继承当前服务的 Python，避免再启动另一份解释器；独立执行生成脚本时采用相同的环境选择顺序。Node 仍可由 `SOP_NODE_PATH` 指定，并保留可选的本机 Excel 生成环境和 PATH 查找。

`data/service.json`、`data/service.pid` 是旧版后台进程的身份记录，不是当前启动配置。迁移后不要把旧 PID 或旧解释器路径直接改成新值；当前前台入口不依赖这些文件，也不会重新创建它们。旧服务仍在运行时，启动器仅在进程身份核对成功后接管。

**Excel 运行依赖：** 安装 `requirements.txt` 后，维护表、网页导出和快照备份都可由 Python 独立生成，适用于没有 Codex 运行环境的内网机器。若本机已有 `@oai/artifact-tool`，程序仍可使用 Node 生成；该包缺失或 Node 无法启动时自动转用 Python。设置 `SOP_EXCEL_ENGINE=python` 可直接使用 Python 生成。`scripts/node_modules` 是可自动重建的本机链接，不提交到 Git。

**Excel编辑与回填：** 导出时保留明细，可填写“车型总量（不分版本）”行或版本月计划；取消明细后，直接填写车型行的月计划，修改后仍可导入同一份计划。车型总量填写值优先，0表示明确零值，清空并导回后恢复明细自动汇总；未修改的自动汇总值不转成手工总量。锁单、年度合计、品牌合计和总计不作为计划输入。普通车型计划表也可导入，无需版本列或隐藏的导出标识：按品牌、带年款车型和月份匹配，只写入非空计划（含0）；空白及缺行保留原值，不停用车型。带标识的导出表仍按导出基准识别修改，支持清空总量。 网页新导出文件下载前会完成回导校验；旧页面请求缺少必要标识时提示Ctrl+F5刷新，不再返回无法回导的只读下载。 Excel将纯整数保存为文本（如“100”）时也可识别为计划量；对数值单元格紧邻整数的浮点存储误差（如2999.9999999999995）按整数3000导入；真实小数仍报错，不进行通用四舍五入。数量区统一使用普通整数格式（0），不使用货币格式；无效输入会提示具体单元格、车型、月份、实际读取值及原单元格格式，公式不会作为计划值读取。导入校验失败后请保存Excel并重新选择文件，页面会重新读取新内容。

**未来车型提前排量：** 先点击“网页维护”，再在车型汇总行点击“新增车型”，直接在原表填写品牌、带年款的车型和各月计划量，无需锁单文件或版本明细。保存后清除原品牌/车型/搜索筛选，便于找到新车型；没有实际锁单时保持空白，不补0。手工车型及计划在刷新、重启和Excel往返后保留，后续真实版本来源出现时仍保留车型总量优先规则。

**锁单口径：** 默认将锁单选配表“版本／数量”行作为分版本锁单，将“交车锁单／数量”行作为车型锁单，两者独立保留原值，不要求合计一致、不分摊。新环境缺少本地 `data/source_settings.json` 时也沿用此口径；显式来源配置或命令行参数仍可覆盖默认。已有空值缓存可在更新后到“数据与规则”点击“刷新销量文件”重新读取，在线计划不变。源文件没有提供的月份仍留空。

**共享代际规则：** 将“SOP维护”和“订单分析”放在同级目录，保留 `../订单分析/scripts/config/shared_config.py` 的 `MERGE_GROUPS` 字典。看板每次读取此相对路径，不硬编码车型映射；规则修改后刷新即生效。页面统一按汇总代际展示，不再选择口径。汇总车型可直接填写月度总量，单代际和版本可在同一张表展开维护；同月汇总填写值优先，清空后恢复成员单代际自动相加（各单代际仍优先其车型总量）。0是明确零值，父子不重复计数。没有单代际计划也可先维护汇总总量。未参与汇总的车型保留原有独立年款。规则缺失或无效时会明确报错，不混用旧目录。该外部配置由“订单分析”项目维护，不复制进本仓库。

**输入路径：** `--source-dir`（数据导入命令）或网关 `source_dir` 显式配置优先；默认读取顺序为 `SOP_SOURCE_DIR`、`SHARED_DATA_ROOT/订单汇总`、同级 `../共享数据/订单汇总`，最后仅在同级共享根不存在时兼容 `input_file/`。`SOP_SOURCE_DIR` 和 `SHARED_DATA_ROOT` 支持相对 SOP 项目根目录的路径，例如 `SHARED_DATA_ROOT=../共享数据`；也兼容绝对路径，不随启动时的当前目录改变。显式指定的共享根或已存在的共享根缺少订单文件时会报告缺失，不改读旧副本。订单汇总目录只提供只读输入；计划维护表默认位于共享根的 `SOP计划/SOP计划维护.xlsx`，数据库和规则仍由原项目维护。其他汇总报表不会加入 SOP 销量计算。

使用共享数据时，无需创建或保留本项目的空 `input_file/` 目录。该目录仅用于没有共享根的独立运行场景，届时按需创建并放入实际输入文件。

**计划表路径：** 网关 `plan_file` 或命令行 `--plan-file` 显式路径沿用既有优先级，其次为 `SOP_PLAN_DIR/SOP计划维护.xlsx`、`SHARED_DATA_ROOT/SOP计划/SOP计划维护.xlsx`、同级 `../共享数据/SOP计划/SOP计划维护.xlsx`；没有共享根时兼容 `input_file/SOP计划维护.xlsx`。`SOP_PLAN_DIR` 支持相对 SOP 项目根目录的路径，例如 `../共享数据/SOP计划`。创建与同步维护表写入所选计划目录，销售源目录不参与此选择。门户预览仍将计划表复制到隔离目录，并通过网关 `plan_file` 绑定该副本。

**数据与规则路径：** `SOP_DATA_DIR`（默认 `./data`）和 `SOP_SHARED_CONFIG`（例如 `../订单分析/scripts/config/shared_config.py`）的相对值也按 SOP 项目根目录解析。服务默认数据库目录及数据导入命令默认输出遵循 `SOP_DATA_DIR`；显式 `--data-dir` / `--output` 优先，网关 `data_dir` / `plan_file` 继续保持既有最高优先级和绝对路径校验。运行时会解析为绝对路径；不需要在本地配置中写死盘符。

## 目录

| 路径 | 用途 | 提交到 Git |
| --- | --- | --- |
| `server.py` | HTTP 服务与启动入口 | 是 |
| `sop/` | 数据读取、计划维护、汇总规则、Excel 同步及备份模块 | 是 |
| `web/` | 页面和图标 | 是 |
| `scripts/` | Excel 生成与数据检查脚本 | 是，`node_modules` 除外 |
| `tests/` | 自动化测试 | 是，生成文件除外 |
| `docs/` | [业务规则与使用说明](docs/业务规则与使用说明.md) | 是 |
| `../共享数据/订单汇总/` | 只读销售来源；与其他项目共用 | 否 |
| `../共享数据/SOP计划/` | 可同步读写的 `SOP计划维护.xlsx` | 否 |
| `input_file/` | 无共享根时按需创建的独立项目兼容输入目录；共享模式无需保留 | 否 |
| `data/` | 数据库、来源解析、设置、快照及日志 | 否 |
| `output_file/` | 临时导出和本地核验文件 | 否 |

业务模块集中在 `sop/` 包，根目录只保留 `server.py` 作为 Python 启动入口；运行数据与临时文件通过 `.gitignore` 排除。换电脑时，应迁移 `data/` 及实际使用的共享输入和计划目录，以保留当前业务状态；只有独立模式使用了 `input_file/` 时，才需额外迁移该目录。不要仅依靠 Git 仓库保存计划或历史快照。

需要手动刷新销量缓存时，在项目根目录运行 `../.venv/Scripts/python.exe -m sop.data`；只读检查原始 Excel 可运行 `../.venv/Scripts/python.exe scripts/inspect_sales.py`。非 Windows 使用对应的 `../.venv/bin/python`。

## 验证

```powershell
../.venv/Scripts/python.exe -m unittest discover -s tests -v
```

本机已安装 Microsoft Excel 时，可用原生只读打开检查生成文件。此检查使用正常打开方式，遇到需要修复的文件会失败，并核对标题合并、列宽及隐藏列：

```powershell
./tests/verify_excel_native.ps1 -Paths ./tests/artifacts/inline-layout/export.xlsx
```

详细的业务口径、表格维护、导入导出和快照规则见[业务规则与使用说明](docs/业务规则与使用说明.md)。


## 单一源码与门户接入

本仓库是 SOP 唯一业务源码，原有独立启动方式保留。门户以前缀代理方式接入，或消费本仓库构建的发布产物。身份、只读与数据路径配置参见 [门户接入说明](PORTAL-INTEGRATION.md)。
